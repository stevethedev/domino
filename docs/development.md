# Working on Domino

Domino is a Tauri 2 app: a React + TypeScript UI on a Rust core. Config, secrets and Jira calls all go through Rust over IPC, so the UI never sees credentials.

```
React UI  --invoke()-->  Rust core (src-tauri)  -->  MockBackend (fixtures) or HttpBackend (Jira REST v3)
```

## Checks

| Command                                                   | Does                                                                          |
| --------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `npm run check`                                           | Types, oxlint, Prettier (140 columns), knip. `npm run fix` fixes what it can. |
| `npm test`                                                | Vitest                                                                        |
| `cd src-tauri && cargo fmt && cargo clippy --all-targets` | Rust format and lints                                                         |
| `cd src-tauri && cargo test`                              | Rust tests (HTTP and OAuth against wiremock)                                  |

CI runs them all on every push to `main` and every PR, and fails on warnings.

The Rust lints are strict on purpose: every clippy group but `restriction`, plus some restriction lints, so no `unwrap`, `expect`, indexing or `print` outside tests. Suppressions need a reason: `#[expect(..., reason)]`, or `#[allow]` when the lint only fires on some platforms or inside a dependency's macro.

The toolchain is pinned in `src-tauri/rust-toolchain.toml` so local and CI clippy agree. Bump the `toolchain:` lines in `.github/workflows/` with it.

## Mock data

The dev builds serve `fixtures/mock/`, regenerated by `node scripts/gen-mock-fixtures.mjs` with dates relative to today. The mocks understand a little JQL (`project`, `key`, `parent`, `statusCategory`, `issueLinkType`, joined with AND), and the signed-in user is Jonas Berg.

To fake an outage, run `DOMINO_MOCK_FAIL_SITES=partner npm run dev`, or add `?failSite=partner` in the browser.

## Where things live

| Path             | What's there                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `src/graph/`     | Pure, tested logic: graph building, cycles, layout (ELK in a Web Worker), insights, schedule, releases, traversal, folding |
| `src/data/`      | Loading across sites, through Tauri or fixtures                                                                            |
| `src/state/`     | Hooks and saved preferences                                                                                                |
| `src/ui/`        | React components, which only use `src/graph/types.ts`                                                                      |
| `src/styles/`    | `tokens.css` (every colour, size and shadow, light and dark) and a stylesheet per surface                                  |
| `src-tauri/src/` | Rust: config, keychain, IPC commands, `jira/{http,mock,oauth}.rs`                                                          |

A few rules the graph follows:

- A ticket is `siteId:key`, so the same key on two sites is two tickets.
- Links are read from both ends and deduped.
- A remote link to `{baseUrl}/browse/{KEY}` on a configured site becomes an edge.
- Layout only uses blocking links, so blockers end up on the left.
- Story points come from `customfield_10016`. For another field, change `FIELDS` in `src-tauri/src/jira/http.rs` and `nodeFromIssue` in `src/graph/buildGraph.ts`.

## Styling

Use the tokens in `src/styles/tokens.css`, not hard-coded values: type scale, 4px spacing grid, radii, shadows, motion, z-index layers, control height and colours (with dark mode). `src/styles/base.css` styles controls with `:where()`, so component classes override them without specificity fights. Icons are in `src/ui/Icon.tsx`: 24px grid, 2px strokes, `currentColor`.

## Releases

See [`.changeset/README.md`](../.changeset/README.md). In short:

1. Add a changeset (`npm run changeset`) to anything users would notice.
2. The bot keeps a "Version Packages" PR open on `main`.
3. Merging it tags the release, which builds signed macOS, Windows and Linux installers into a **draft** GitHub release.
4. Publishing the draft ships it, including to installed copies.

### In-app updates

The app checks the latest published release's `latest.json` shortly after launch and every 6 hours; Settings &rarr; **App version** can turn that off or **Check now**. Downloads are verified against `plugins.updater.pubkey` in `src-tauri/tauri.conf.json` before installing. Dev builds only check when asked.

One-time signing setup:

1. In an interactive terminal, run `npx tauri signer generate -w ~/.tauri/domino.key`. Back up the key and password; without them, installed copies can't verify updates.
2. Put `~/.tauri/domino.key.pub`'s contents in `plugins.updater.pubkey`.
3. Add the repo secrets `TAURI_SIGNING_PRIVATE_KEY` (the key file's contents) and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

Only the release workflow builds update files (via `src-tauri/tauri.release.conf.json`), so local builds don't need the key. To preview the update prompt in `dev:web`, set `localStorage["domino.dev.fakeUpdate"] = "0.9.0"`, reload and **Check now**.

## App icon

Three falling dominoes. Sources are in `assets/brand/`: `icon.svg` (48px+), `icon-small.svg` (16&ndash;32px) and `mark.svg` (just the tiles). To regenerate:

1. `python3 assets/brand/build-icons.py` (also writes `public/favicon.svg`).
2. `npx tauri icon assets/brand/icon.svg`, then delete the `android/` and `ios/` folders it makes.
3. Re-render the small art over the 16&ndash;32px sizes.
